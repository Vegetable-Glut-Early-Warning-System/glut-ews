# Vegetable Glut Early Warning System – Parent Dataset (v1.0)
Project J26-ISE-306 · Crops: tomato, pumpkin, cucumber, winged bean, green chilli · Period: 2018/19 Maha – 2025 Yala (weekly data 2019-01-01 – 2025-12-31) · 25 districts · 12 economic centres

## Location in the project
The dataset lives in `data/glut_ews.duckdb` (schemas `raw`, `core`, `outputs`, `outputs_history`, `views`), with read-only exports in `parquet/<schema>/<table>.parquet`. View definitions are in `sql/views.sql`; `scripts/rebuild_db.py` applies module outputs and core updates and regenerates the exports. See `docs/TEAM_GUIDE.md` for the full workflow.

## Layers
| Schema | Content | Rule |
|---|---|---|
| `raw` | Extracts of the source files exactly as published: original spellings, per-acre units, week 53, revision conflicts, the suspect pumpkin value | Never edited |
| `core` | Standardised parent dataset: canonical names, consistent units, typed columns, one row per key, `provenance` on every fact row | Only cleaning that every module would do identically |
| `outputs` | Active module outputs consumed downstream (`c1_glut_season`, `c2_pressure_score`, `c3_training_label`, `c3_risk_prediction`, later `c4_advisory`) | Currently `placeholder_v0`; replaced only through `publish_output` + `scripts/rebuild_db.py` |
| `outputs_history` | Earlier output versions archived by the rebuild | Created on the first replacement |
| `views` | `component1_dataset` … `component4_dataset` assembled by SQL from core + outputs (the agreed column lists) | Not stored – always consistent with core |

Missing values, outliers, lags, scaling and aggregation choices are **module preprocessing**, not core.

## Provenance vocabulary
- **observed** – taken from a published source (unit conversion only)
- **estimated** – deterministic derivation from observed data (e.g. district extent = DOA district share × DCS national extent; interpolated CCPI; corrected value with documented rule)
- **synthetic** – generated by a documented model with assumptions and random variation (market arrivals, non-Colombo centre prices, winged bean prices, district shares for seasons without DOA district tables, weather after 2024-06-08)
- **missing** – not collected at source (kept as NULL for modules to handle)

## Quick start
```python
from glut_ews.common import load, validate, lag_by_season

prices = validate(load("core.market_prices_weekly"), "core.market_prices_weekly")
c3 = load("views.component3_dataset")                     # agreed C3 columns + split
c3 = lag_by_season(c3, ["historical_glut_label", "harvest_wholesale_mean_rs_kg", "market_arrivals_t"],
                   ["district", "crop"], k=1)             # previous-season values for pre-planting prediction
train = c3[c3.split == "train"]
```
(Requires `uv pip install -e .` from the project root.) SQL directly:
```python
import duckdb
con = duckdb.connect("data/glut_ews.duckdb", read_only=True)
con.sql("SELECT crop, AVG(wholesale_price_rs_kg) FROM core.market_prices_weekly WHERE provenance='observed' GROUP BY crop").df()
```
Parquet without DuckDB: `pd.read_parquet("parquet/core/supply_season.parquet")`. Excel cannot open Parquet; `python scripts/rebuild_db.py --csv` writes viewing copies to `csv_view/`.

## Rules for all modules
1. **Shared split** (`core.dim_season.split`): train ≤ 2023 Yala · validation 2023/24 Maha – 2024 Yala · test 2024/25 Maha – 2025 Yala.
2. **No look-ahead**: features for season *t* use information available before *t* starts. In the component views, prices, arrivals, wastage, production, in-season weather and `historical_glut_label` describe season *t* itself – lag them (`lag_by_season`) before using them to predict *t*.
3. **C4 consumes `outputs.c3_risk_prediction`**, never `c3_training_label`.
4. **Replacing a placeholder**: `publish_output(df, table, version="v1")`, then the schema owner runs `scripts/rebuild_db.py`; the previous version is archived in `outputs_history`. Re-run downstream modules.
5. **Validate on load** (`validate`) and run `pytest` before committing.

## Known gaps
- Oct–Dec 2025 weeks belong to 2025/26 Maha, which has no published production yet → `season_extent_ha` NULL in component 1 for those weeks.
- HARTI did not collect prices in some weeks (2019 W16, 2020 W11–18 and W41–52, 2021 W1–2, W21–24, W34) → NULL prices at all centres; retail has a few additional gaps.
- See `docs/known_issues.csv` (also `core.known_issues`) for every source defect and how core handled it.
